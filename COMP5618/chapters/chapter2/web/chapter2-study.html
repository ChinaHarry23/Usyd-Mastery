Two Models of the Same Stack

Before touching a single frame, the deck fixes the vocabulary: one model explains, the other one runs.

The distinction the deck insists on: the OSI model is a way to conceptualise network systems, where each layer is an abstraction from the one below it. TCP/IP is what is actually used for establishing a connection and communicating over the Internet — a more simplified and flexible model in which TCP and IP are two separate protocols that work together to manage the movement of data packets.

Encapsulation

Each layer takes the data handed down by the layer above and wraps it in its own header (and sometimes a trailer). The name of the wrapped unit changes at every layer, which is why the exam asks about the PDU (protocol data unit) and not just “the data”. Receiving hosts reverse the process: strip, check, hand up.

Why a security unit starts at Layer 1–2: the higher layers are abstractions built on trust that the lower ones provide. If you can influence Layer 2 — which device receives a frame, which MAC address a switch believes — every protocol above inherits the lie. That is the recurring theme of this chapter.

Layer 1: Bits on the Medium

Layer 1 is the physical layer. It deals with bits and how they are modulated, multiplexed and encoded onto the medium.

The three verbs of Layer 1

Encode — turn a bit stream into a signal the receiver can recover (line codes such as Manchester or 4B/5B, or modulation such as ASK, FSK, PSK and QAM on radio). Modulate — impose that signal on a carrier. Multiplex — share one medium between several channels, by frequency (FDM), by time (TDM) or by wavelength in fibre (WDM).

MediumSignalTypical LAN useWhat an attacker needs
Twisted pair (Cat5e / Cat6)Electrical, differential pairsWall sockets, patch panels, 1 GbE and up to 10 GbE on short runsPhysical access to the cable, a patch panel or an unsecured wall port
Fibre opticLightBuilding backbones, long runs, links between switchesPhysical access plus a bend or splitter; no electrical emanation to exploit
CoaxialElectrical, shared busLegacy LANs, cable access networksA tap anywhere on the shared segment
Radio (802.11)RF in licensed-exempt bandsAccess points, client devicesNothing physical — proximity and an antenna are enough
The defender's reading of Layer 1: if an adversary can reach the medium, they can copy every bit on it. That is why physical access is treated as a full compromise rather than as a prerequisite to one, and why locked comms rooms, port security and encrypted protocols above Layer 2 are the compensating controls.

Layer 2: Frames on One LAN

Layer 2 deals with frames and is concerned with how data is transmitted between devices on the same LAN. Its services, as the deck lists them: data transfer, error checking and collision detection.

Why the frame has an address at all

A packet can travel across the world, but a frame only ever crosses one link. Before sending data on a LAN a device must identify the MAC address of the destination device — that address is what the switch reads to decide which port to use. The frame is therefore rebuilt at every hop while the packet inside it stays the same.

The Ethernet II frame field by field

FieldSizePurposeAttack angle
Preamble7 bytesAlternating 1/0 pattern so the receiver can lock onto the bit timingNot addressable by software; jamming is a Layer 1 problem

EtherType / length2 bytesWhat is inside: 0x0800 IPv4, 0x0806 ARP, 0x86DD IPv6, 0x8100 802.1Q tagMismatched EtherType is a classic IDS evasion trick

Frame check sequence (FCS)4 bytesCRC-32 over the frame; corrupted frames are discardedDetects accidents, not tampering — it is not a signature

The two sizes worth memorising

  • Minimum frame: 64 bytes — header and trailer are 18 bytes, so a payload under 46 bytes is padded.
  • Maximum frame: 1518 bytes — 1500 bytes of payload (the MTU) plus 18 bytes of header and trailer.
  • An 802.1Q tag inserts 4 bytes, giving a 1522-byte maximum.

Why the minimum exists

On a shared half-duplex segment, collision detection only works if the frame is still being transmitted when the signal can travel to the far end of the segment and back. A frame shorter than 64 bytes could finish before a collision was noticed — the classic runt. Modern switched full-duplex links rarely collide, but the size rules remain.

Worked example — sizing and reading one frame. A host sends a 20-byte ARP request inside a standard Ethernet frame. How big is the frame on the wire, and how much of it is overhead?

1

Add the header. Destination MAC (6) + source MAC (6) + EtherType (2) = 14 bytes.

2

Add the trailer. The FCS is 4 bytes, so header plus trailer is 18 bytes.

3

Apply the minimum-payload rule. The ARP message is 28 bytes on the wire in practice (see the ARP section), but take this example's 20 bytes: it is below 46, so it is padded to 46.

4

Total. 14 + 46 + 4 = 64 bytes — exactly the minimum frame size. Payload efficiency is 20/64 ≈ 31%, and the real ARP message at 28 bytes gives 28/64 ≈ 44%.

5

Read it in a capture. Wireshark shows the padding as trailing zero bytes that the ARP dissector ignores, which is why the frame length reported for an ARP request is 42 bytes of protocol data inside a 60-byte (FCS-excluded) frame.

A capture shows a 60-byte Ethernet frame (excluding the FCS) carrying an ARP request. Why is the frame not 42 bytes?
The payload has been encrypted, which adds bytes
The payload is padded to reach the 64-byte minimum frame size
The 8-byte preamble and SFD are included in the captured length

MAC Addressing

Definition

Devices communicate on Layer 2 by use of MAC addresses. Every device has a unique MAC address (48-bit), which is programmed in the factory. Different manufacturers have different MAC ranges allocated to them, which can allow remote identification of hardware.

BitsNameMeaningSecurity consequence
24 (first half)OUI — organisationally unique identifierThe manufacturer or vendor block assigned by the IEEEPassive reconnaissance: a capture reveals the vendor mix of a network without touching a single host
24 (second half)NIC-specificAssigned by the manufacturer to that interfaceUniqueness is a manufacturing promise, not a technical guarantee
Bit 0 of the first octetI/G — individual/group0 = unicast, 1 = multicast (the broadcast address is the all-ones case)Multicast and broadcast frames are delivered to everyone in the broadcast domain
Bit 1 of the first octetU/L — universal/local0 = factory-assigned, 1 = locally administeredA locally administered address is how a spoofed or randomised MAC stays valid

00:1A:2B:3C:4D:5E    colon-hexadecimal (Linux, macOS, Wireshark filters)
00-1A-2B-3C-4D-5E    hyphen-hexadecimal (Windows)
001a.2b3c.4d5e      Cisco dotted-quad

Special values:
FF:FF:FF:FF:FF:FF   broadcast — every station in the broadcast domain
01:00:5E:xx:xx:xx   IPv4 multicast mapped into Ethernet
33:33:xx:xx:xx:xx   IPv6 multicast
What a MAC address is not: it is flat and non-hierarchical. It says nothing about where a device is, so it cannot be routed beyond the local segment, and it does not have to be believed. A MAC address is an identifier a device claims, which is exactly why MAC filtering is a speed bump and not an access control.
Your capture shows a device whose MAC begins 00:1A:2B. What have you actually learned?
The vendor the interface block was allocated to, which may hint at the device class
The network the device is currently attached to
Proof that the frame genuinely came from that manufacturer's device

ARP: Finding the MAC Behind an IP

The deck gives the reason ARP exists in one line: before sending data on a LAN, a sending device must identify the MAC address of the destination device — and if the sender only has an IP address, it can use ARP to determine the corresponding MAC address.

Address Resolution Protocol

ARP resolves a known IPv4 address on the local segment into the MAC address that owns it. It is a link-layer helper that straddles the Layer 2/3 boundary: the question is about an IP address, but the answer has to travel in an Ethernet frame. IPv6 does the same job with Neighbor Discovery instead.

ARP message fieldSizeValue in an Ethernet/IPv4 request
Hardware type2 bytes0x0001 (Ethernet)
Protocol type2 bytes0x0800 (IPv4)
Hardware / protocol length1 + 1 byte6 and 4
Opcode2 bytes0x0001 request, 0x0002 reply
Sender MAC and IP6 + 4 bytesThe asking host's own addresses
Target MAC and IP6 + 4 bytesTarget MAC is all zeros in a request, filled in the reply
Total28 bytesInside a 14-byte Ethernet header, padded to the 64-byte minimum frame

Request: broadcast

The sender does not know who owns the target IP, so it has to ask everyone. The request goes to FF:FF:FF:FF:FF:FF with the target MAC field zeroed. Every station in the broadcast domain receives it; only the one whose IP matches acts on it.

Reply: unicast

The target already has the requester's MAC from the request, so it answers directly. Both sides then keep a short-lived ARP cache entry, which is why the second exchange with the same host is silent.

The design flaw that defines the attack: ARP has no authentication, and a host will happily accept and cache replies it never asked for. A gratuitous ARP — an announcement sent without a request — can overwrite a correct entry. That single property is the root of ARP spoofing, and it is why Layer 2 interception is a chapter in an offensive-security unit.
Why is the ARP request broadcast while the reply is unicast?
The requester knows only the IP address, but the responder learns the requester's MAC from the request
The request is larger, so it needs the extra bandwidth of a broadcast
Both are broadcast, and the reply only looks unicast in a capture

Switching, Broadcast Domains and VLANs

A switch is the Layer 2 device that makes a LAN work: it forwards frames by MAC address and, in doing so, decides who can see whose traffic.

How a switch decides

For every frame the switch learns the source MAC and the port it arrived on, then looks up the destination MAC in that table. A known unicast is forwarded out of exactly one port; an unknown unicast, a broadcast or a multicast is flooded out of every other port in the same VLAN. Entries age out so that a device which moves is relearned rather than black-holed.

Collision domain vs broadcast domain

A switch gives every port its own collision domain — that is what “collision detection” from Layer 2 becomes in a modern switched LAN. It does not split the broadcast domain: every port in the same VLAN still receives every broadcast and every unknown unicast.

VLANs: what they buy

In the switch, ports are assigned VLAN IDs. A different VLAN ID effectively puts a port on a different virtual switch, and all ports with the same VLAN ID are on the same virtual switch. Traffic cannot pass between VLANs without a Layer 3 device, so VLANs give task segregation, lower communication overhead and a smaller blast radius — the deck's own list of what subnetting and segmentation assist with.

Two hosts are on the same switch but in different VLANs. What is true?
They receive each other's broadcast frames, just as if they shared a VLAN
They are isolated at Layer 2 and need a Layer 3 device to communicate
They merge automatically as soon as the inter-switch link is configured as a trunk

Capturing What Layer 2 Says

Everything in this chapter is visible in a capture. The skill is knowing where to stand and how to filter.

Three ways to see traffic that is not addressed to you

Promiscuous mode — the interface hands up every frame it receives on its segment, not just frames addressed to it. Monitor mode — the wireless equivalent: the radio reports 802.11 frames, including management frames, instead of only the traffic of the network it joined. Port mirroring (SPAN) or a network TAP — the switch, or a physical device in the cable, copies traffic to a capture port. Promiscuous mode alone is useless on a switched network: the switch will not send you other people's unicast frames.

Reading order in a capture: start at Layer 2 and work up. Which source MAC is repeating itself? Is the destination a broadcast? Is the EtherType what the traffic claims to be? A host that answers an ARP request for an address it does not own, or a port that suddenly sources frames for twenty MAC addresses, is visible before you look at a single byte of payload.
Scope, ethics and the law: capturing traffic on a network you do not own or have written authorisation to test is out of scope for this unit and, in Australia, potentially a criminal offence under the Criminal Code Act 1995 (Part 10.7). Everything in this chapter is practised inside your own isolated lab VMs — the VirtualBox NAT networks you build in Tutorial 2 — and nowhere else.

The Layer 2 hiding place: a firewall that operates at Layers 3 and 4 has no opinion about a frame whose EtherType is ARP, or about two hosts on the same VLAN talking directly. Everything the switch does — flooding, learning, VLAN enforcement — happens beneath the security device's field of view.

The Layer 2 Attack Surface

Layer 2 was designed for a trusted building, not for an adversary on the same wire. Each technique below is a consequence of a design decision you have already met in this chapter.

TechniqueWhat it exploitsWhat the attacker gainsControl that stops it
ARP spoofing / poisoningARP replies are unauthenticated and unsolicited replies are cachedTraffic for the gateway is redirected through the attacker: on-path visibility and modification at Layer 2Dynamic ARP inspection with DHCP snooping, static ARP for critical hosts, port security

Rogue DHCPClients accept the first offer; there is no authenticationSupplies a false gateway and DNS server, which is ARP spoofing one step earlierDHCP snooping with trusted ports
Rogue access point / evil twinClients trust a network nameAttracts clients onto the attacker's segment, or harvests credentials with a captive portal802.1X for wireless, WPA3, wireless intrusion detection, client-side network profiles
Spanning-tree manipulationBPDUs are unauthenticated, and the root bridge is elected by whoever claims it bestRedirects the topology so traffic crosses the attacker's linkBPDU guard and root guard on access ports

The pattern behind all seven

Layer 2 protocols were written when the wire was the trust boundary. None of them authenticate the speaker: not ARP, not DHCP, not DTP, not BPDU. The mitigations are all variations of the same move — make the switch, not the frame, the authority on who may say what.

What still works when Layer 2 fails

Encryption and integrity above the link layer: TLS, SSH, signed updates, and anything that authenticates the endpoint rather than the path. Layer 2 interception gives an attacker a position, not automatically a secret — which is exactly why the unit moves on to Layers 3 and 4 next week.

Worked example — triaging a Layer 2 symptom. Users on one VLAN report that the web proxy is “slow and sometimes logs them out”. A capture on a SPAN port shows the gateway's MAC address appearing as the source of frames arriving from three different switch ports.

1

State what the evidence rules in. One MAC address cannot legitimately originate from three ports. Either a device moved, or something is claiming the gateway's identity. Frame-by-frame, check whether an unsolicited ARP reply carrying the gateway's IP appears before the change — that is the signature of poisoning.

2

Test the innocent explanation first. A laptop docking station, a virtual machine with a bridged adapter, or a redundant link can all present one MAC on two ports. Three ports at once, correlated with the start of the complaints, is what makes the benign explanation fail.

3

Name the impact precisely. If the gateway mapping is poisoned on the clients, their traffic is being relayed through the attacker's host. That is on-path: confidentiality is lost, and so is integrity, because the attacker chooses what to forward. “Slow” is the visible symptom of a deliberate relay, not of congestion.

4

Contain, then confirm. Identify the port, shut it or port-disable it, and clear the affected ARP caches. Re-check the switch's MAC table for the gateway address — it should resolve to exactly one port again. Container first, because every minute of relayed traffic is another minute of exposure.

5

Fix the condition, not the incident. The root cause is that the switch accepted unauthenticated claims. Dynamic ARP inspection with DHCP snooping, port security that limits learned addresses, and 802.1X on access ports remove the assumption. Report the finding with the evidence, the impact, the containment and the control that prevents recurrence.

Why does MAC flooding cause a switch to leak unicast traffic?
The MAC table overflows, and an unresolvable unicast is flooded to every port in the VLAN
The VLAN configuration is overwritten, merging all VLANs into one
The switch starts broadcasting frames onto other networks and stops checking the FCS

Tutorial 2: Reaching a Host Behind a Jump Host

Tutorial 2 builds two VirtualBox NAT networks — a “public” one standing in for the Internet and a “private” one standing in for a company's internal network — then pivots from Kali to a target running DVWA. The layer model is what decides which pivot works.

MachineInterfaces and networksRole
KaliOne interface on the Public NAT networkThe attacker workstation; can reach the jump host but not the private network directly
Jump host (Ubuntu)Two interfaces: one on Public, one on Private; SSH enabledThe pivot. It is the only host that can see both networks
Target (Ubuntu)One interface on the Private NAT network onlyRuns Apache and MySQL serving DVWA, the intentionally vulnerable web application
Tutorial commands, in the order the tutorial gives them

# on the target: make the web server available
sudo apt install apache2
sudo systemctl enable apache2
sudo systemctl start apache2

# from Kali: forward a local port through the jump host to the target's port 80
ssh -L 8888:<target host>:80 user@<jump host> -N

# then browse to http://127.0.0.1:8888/ on Kali

Worked example — the port forward, and the wall it hits. The tutorial's command is ssh -L 8888:<target host>:80 user@<jump host> -N. Read it as three addresses and one rule.

1

Split the argument. 8888 is the port opened on Kali. <target host>:80 is where the jump host is asked to connect, from its own point of view. user@<jump host> is who does the asking. The -L means “local forward”: the listening socket is on our side of the tunnel.

2

Follow one connection. Kali's browser connects to 127.0.0.1:8888. SSH carries that byte stream, encrypted, to the jump host. The jump host opens a new TCP connection to the target on port 80 and splices the two together. The target sees a connection from the jump host, not from Kali — which is exactly why this is a pivot and not a direct route.

3

Know what -N does. It tells SSH not to run a remote command — the connection exists only to carry forwards. Removing it gives you an interactive shell on the jump host as well, which is handy while testing. The -J flag is the related shortcut for reaching a host through a jump host.

4

Find the boundary. The tunnel forwards one TCP service. The tutorial makes the consequence explicit: nmap uses many protocols, including ICMP, and ICMP is neither TCP nor UDP, so it cannot be forwarded by SSH or any proxy — those only forward at the application layer. You cannot scan what you cannot carry.

5

Choose the right tool. When the whole private network has to be reachable — several ports, several hosts, non-TCP protocols — the tutorial configures OpenVPN on the jump host, with client keys and its own certificate authority, so Kali joins the private network at Layer 3 instead of borrowing one port at a time.

Lab scope: every address, command and target in this section belongs to the isolated VirtualBox NAT networks you build yourself. Do not point any of these techniques at hosts you do not own or have written authorisation to test.
Why can an SSH port forward carry an HTTP request but not an ICMP echo request?
SSH forwards a TCP stream, and ICMP is neither TCP nor UDP, so there is nothing for the tunnel to carry
ICMP is encrypted by the IPsec layer, which SSH cannot decrypt
ICMP is always blocked by the jump host's firewall, so the tunnel never opens

Week 2 Recap

One model explains, one model runs

OSI is the seven-layer abstraction; TCP/IP is the four-layer model actually used, with TCP and IP as separate cooperating protocols. Every layer wraps what it receives.

Framing

Layer 1 is bits, Layer 2 is frames

Layer 1 modulates, multiplexes and encodes bits onto the medium. Layer 2 moves frames between devices on the same LAN and adds data transfer, error checking and collision detection.

Definitions

48-bit MAC, learned not asserted

The OUI says who made the interface; the switch learns which port it lives on. MAC addresses are flat, so they cannot be routed, and nothing authenticates them.

Addressing

ARP is the seam between Layer 2 and 3

“Who has this IP?” broadcast, answered by unicast, cached without authentication. That last property is the whole Layer 2 attack surface in one sentence.

The flaw

Check yourself

Can you name the seven OSI layers in order, say what a frame's destination MAC is for, explain why an ARP request is broadcast, and give one mitigation each for ARP spoofing, MAC flooding and VLAN hopping?

Prepare for the tutorial

Be able to draw the Tutorial 2 topology from memory: which interface on which network, which machine can see which, and why the SSH forward reaches one service while the VPN reaches the whole subnet.
