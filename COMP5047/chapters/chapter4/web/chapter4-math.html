Foundations: the arithmetic of analogue input and output

Week 4 is the most quantitative week of the unit. Four relationships do most of the work: how a voltage becomes an integer (quantisation), how an integer becomes an average voltage (PWM), how fast a continuous signal can be sampled (sampling time), and how raw counts become physical units (calibration). This page states each one, works a number through it, and ends with the bring-up checklist that turns the arithmetic into a wired, working sensor.

Definitions & symbols

Marks in this unit are usually lost on the difference between a reading and the thing it stands for. These are the definitions to write out exactly.

Analogue and digital signals

An analogue signal is continuous in both time and amplitude: between any two values there is another value. A digital signal takes one of a finite set of levels, and a digital representation of an analogue signal is a finite list of numbers — discrete in time (sampling) and discrete in amplitude (quantisation).

Resolution, reference and code

Resolution \(N\) is the number of bits per conversion, so a converter has \(2^{N}\) codes. The reference voltage \(V_{REF}\) defines the top of the range. The code is the integer the converter returns — 0…1023 for the Uno, 0…255 for its PWM output. One LSB (least significant bit) is the voltage step that one code represents.

Duty cycle, ratiometric, and calibration

Duty cycle \(D\) is the fraction of a PWM period the output spends high. A measurement is ratiometric when the sensor and the ADC reference share the same supply, so supply drift cancels. Calibration is the mapping from codes to physical units, established at known reference points.

Quantisation & resolution

The input side is a division problem: a voltage range is divided into a fixed number of equal steps, and the converter reports which step the input fell into.

1. Step size and code count

The converter divides the reference range into \(2^{N}\) steps of equal width:

\[ q \;=\; \frac{V_{REF}}{2^{N}} \qquad\text{and}\qquad V_{in} \;\approx\; k \cdot q \;=\; k\cdot\frac{V_{REF}}{2^{N}} \]

For the Uno: \(q = 5/1024 = 4.883\) mV, and the codes run from 0 (0 V) to 1023 (one step below 5 V).

2. From a voltage to a code, and back

Going in, the converter reports the step the input falls in, clamped at the top of the range:

\[ k \;=\; \min\!\left(2^{N}-1,\ \left\lfloor \frac{V_{in}}{q} \right\rfloor\right) \]

Going out, the reconstruction is \(V \approx k\,q\). Because a code stands for a whole step, the error of an ideal converter is bounded by half a step, \(|e| \le q/2\), and for a signal that sweeps the range the error is roughly uniform, so its RMS value is \(q/\sqrt{12}\).

3. The two conventions you will see in sketches

Arduino code usually writes the inverse as \(V = k \cdot V_{REF}/(2^{N}-1)\), i.e. raw * (5.0 / 1023.0), because map() treats 1023 as the end of the range. The ideal quantiser uses \(2^{N} = 1024\) steps. The two differ by a factor \(1024/1023\) — 0.1 %, far below the noise — but you should be able to say which one your sketch uses and why.

4. Choosing a resolution

Work backwards from the smallest change you must detect, \(\Delta x\), over the range \(X\):

\[ N \;\ge\; \left\lceil \log_2 \frac{X}{\Delta x} \right\rceil \]

and the textbook dynamic-range and signal-to-noise results follow from the same step size: \(\mathrm{DR} = 6.02N\) dB, and \(\mathrm{SNR} \approx 6.02N + 1.76\) dB for a full-scale sine wave. (Those two are standard converter theory rather than lecture material; they are here so that the phrase “10-bit” has a magnitude attached to it.)

Why more bits are not automatically better. Every extra bit halves the step size, and eventually the step is smaller than the noise on the ground, supply and reference. Past that point the extra bits are faithfully digitising noise. This is why a 10-bit converter with a clean layout and a calibration beats a 16-bit converter with a long unshielded cable.

Worked numbers — the quantisation chain for one reading. A potentiometer is wired across 5 V and GND with its wiper on A0. The knob is turned to about three-quarters of its travel.

1

Step size. \(q = V_{REF}/2^{N} = 5/1024 = 4.883\) mV. This single number sets the floor on everything else in the chain.

2

Ideal voltage at the wiper. Three-quarters of the track gives \(V_{in} = 0.75 \times 5 = 3.75\) V.

3

Code. \(k = \lfloor 3.75 / 0.004883 \rfloor = \lfloor 768 \rfloor = 768\). Reconstructing gives \(768 \times 4.883\ \text{mV} = 3.750\) V, so this particular reading happens to land exactly on a step.

4

What the code cannot tell you. Any input between \(768\,q\) and \(769\,q\) — a band 4.883 mV wide — produces the same 768. The reconstruction error is at most 2.44 mV, and the best possible RMS error over a swept input is \(q/\sqrt{12} = 1.41\) mV.

5

Percentage view. As a fraction of the knob's travel the reading is \(768/1023 = 75.07\) %, and one code is \(1/1024 \approx 0.098\) % of the track. That is the finest position change this hardware can report, before any mechanical slop in the pot is considered.

PWM: duty cycle and filtering

The output side is the mirror image. There is no digital-to-analogue converter, so an analogue-looking output is built from time: switch fast, and let the average do the work.

1. Duty cycle, average voltage, and the sketch value

With period \(T = 1/f_{PWM}\) and on-time \(t_{on}\):

\[ D = \frac{t_{on}}{T}, \qquad V_{avg} = D \cdot V_{CC}, \qquad D = \frac{v}{255} \]

where \(v\) is the value passed to analogWrite(). On a 5 V board, \(v = 128\) gives \(D = 0.502\), so \(V_{avg} = 2.51\) V. The output is always either 0 V or 5 V at any instant: the average exists only over a period.

2. Filtering: from switching to steady

A first-order RC low-pass after the pin turns the square wave into a steady level with a small ripple:

\[ f_c = \frac{1}{2\pi RC}, \qquad \Delta V_{ripple} \;\approx\; \frac{V_{CC}\,D\,(1-D)}{f_{PWM}\,RC} \]

The design rule is \(f_c \ll f_{PWM}\) — at least a decade below. Two consequences follow from the same equation: bigger \(RC\) means less ripple and a slower response, because the filter settles in roughly \(5RC\). Ripple is worst at \(D = 0.5\), where \(D(1-D)\) peaks.

3. What PWM cannot do

The average is a voltage, but the current still arrives in pulses. A load that responds faster than one period — a piezo element, a small motor's windings, a photodiode — sees the square wave, not the average. That is why a PWM-driven speaker buzzes at \(f_{PWM}\), and why the same pin powering a sensor will inject switching noise into the measurement.

Worked design — a 2.0 V reference from a PWM pin. Use the Uno's 5 V supply, a PWM pin at ≈490 Hz, and an RC filter that keeps the ripple under 20 mV.

1

Duty cycle. \(D = V_{avg}/V_{CC} = 2.0/5 = 0.4\). In sketch terms \(v = 0.4 \times 255 = 102\).

2

Ripple requirement. \(\Delta V = V_{CC}D(1-D)/(f RC) = 5 \times 0.4 \times 0.6/(490\,RC) = 1.2/(490\,RC) \le 0.02\) V, so \(RC \ge 1.2/(490 \times 0.02) = 0.122\) s.

3

Pick components. \(R = 10\) kΩ and \(C = 22\) µF give \(RC = 0.22\) s and a ripple of \(1.2/(490 \times 0.22) = 11\) mV — comfortably inside the budget.

4

Check the cutoff. \(f_c = 1/(2\pi \times 0.22) \approx 0.72\) Hz, which is nearly three decades below 490 Hz. The filter is doing exactly what it was chosen to do.

5

State the trade-off. The same 0.22 s time constant means the output takes about \(5RC \approx 1.1\) s to reach a new value. If the application needs to change level quickly, the filter has to be smaller and the ripple budget has to grow — or the PWM frequency has to be raised.

Sampling in time

Quantisation limits how finely a value is known. Sampling limits how often it is known — and those are different errors with different cures.

1. Conversion time sets the ceiling

One analogRead() occupies the converter for about \(t_{conv} \approx 100\) µs, so the fastest sampling rate a single channel supports is

\[ f_s \;\le\; \frac{1}{t_{conv}} \;\approx\; 10\ \text{kS/s} \]

and in practice rather less, because the loop has other work to do. Anything faster than that has to be handled by the hardware — an interrupt, a timer, or a dedicated converter.

2. Nyquist, and what aliasing does to a reading

A signal containing frequencies up to \(f_{max}\) is only represented faithfully if

\[ f_s \;\ge\; 2 f_{max} \]

Below that, higher frequencies fold down and appear as a slow oscillation that was never in the signal. The practical consequence for a sensor that only needs slow information — light level, room temperature — is the opposite of the usual advice: sample slowly, and put an RC low-pass in front so that the fast noise is gone before it can alias.

3. Averaging buys resolution back from noise

For \(N_{avg}\) readings corrupted by independent random noise with standard deviation \(\sigma\),

\[ \sigma_{\bar{x}} \;=\; \frac{\sigma}{\sqrt{N_{avg}}} \]

Sixteen readings improve the noise by a factor of four, which costs 1.6 ms at 100 µs per reading. Averaging cannot, however, break the quantisation floor: if the noise is smaller than one LSB, every reading is identical and the average is identical too.

A photoresistor circuit picks up 50 Hz flicker from mains lighting, and the sketch reads it every 100 ms. What is the sensible fix?

Increase VREF so that the flicker is a smaller fraction of the range

Calibration algebra

Two known points define a line. That single fact is behind every calibration you will write this week, including the Arduino's own map().

1. Two points give slope and offset

With a known physical value \(x_1\) at raw reading \(r_1\) and \(x_2\) at \(r_2\):

\[ x \;=\; a\,r + b, \qquad a = \frac{x_2 - x_1}{r_2 - r_1}, \qquad b = x_1 - a\,r_1 \]

Arduino's map() is the same expression in integer arithmetic:

\[ y \;=\; \frac{(x - in_{min})(out_{max} - out_{min})}{in_{max} - in_{min}} + out_{min} \]

and it does not clamp: a reading outside the input range produces an output outside the output range, which is why constrain() belongs next to it.

2. Recovering a resistance from a divided voltage

Since the same current flows through both resistors of a divider, a measured \(V_{out}\) gives the sensor's resistance directly:

\[ R_s = R_f \cdot \frac{V_{CC} - V_{out}}{V_{out}} \quad\text{(sensor on top)} \qquad R_s = R_f \cdot \frac{V_{out}}{V_{CC} - V_{out}} \quad\text{(sensor at the bottom)} \]

This is the step that lets you compare a datasheet curve — which is written in ohms, against lux, force or temperature — with the numbers your sketch is printing.

3. Non-linearity: when two points are not enough

Thermistors, photoresistors and force sensors are strongly non-linear. The standard fixes, in increasing order of effort: piecewise-linear interpolation between a table of measured points; a power law or exponential model fitted to the datasheet; or the Steinhart–Hart equation for a thermistor,

\[ \frac{1}{T} \;=\; A + B\ln R + C(\ln R)^{3} \]

In all three cases the workflow is identical: measure the real device at several known points, compare, and choose the simplest model that stays inside your error budget.

Worked calibration — a force-sensing resistor, and the honest conclusion. The FSR is the top resistor of a divider with \(R_f = 10\) kΩ to ground on a 5 V board. Three known loads are applied and the codes recorded.

1

The measurements. 0 N → \(r_1 = 8\); 9.81 N (1 kg) → \(r_2 = 640\); 19.6 N (2 kg) → \(r_3 = 812\).

2

Fit through the first two points. \(a = (9.81-0)/(640-8) = 0.01552\) N per count, \(b = 0 - a \times 8 = -0.124\) N. So \(F \approx 0.01552\,r - 0.124\).

3

Test it on the third point. The model predicts \(0.01552 \times 812 - 0.124 = 12.5\) N where the true load is 19.6 N — a 36 % error. A straight line through two points does not describe this sensor.

4

Diagnose it. An FSR's resistance falls roughly as \(1/F\), so the conductance is close to linear in force. Converting each code to a resistance with \(R_s = R_f (V_{CC} - V_{out})/V_{out}\), then \(V_{out} = k\,q\), and fitting \(1/R_s\) against force, brings the third point to within a few percent.

5

Say what the design can honestly claim. If the interaction only needs “touched / pressed / squeezed hard”, report three bands and stop. If it needs newtons, calibrate per unit with the real mounting, and state the operating range over which the fit holds. Choosing the weaker claim is a legitimate engineering answer.

Bring-up checklist

Every analogue input in this unit goes through the same eight steps. Run them in order and most problems are caught by step 3 instead of by an hour of guessing.

The one-sentence version of the whole week. A physical quantity is conditioned into a voltage, quantised into a code against a reference, calibrated into units with two known points, and driven back out again as a duty cycle that averages to the voltage you wanted — and every one of those five stages has a number attached to it that you should be able to state.
