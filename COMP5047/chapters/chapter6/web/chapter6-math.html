Foundations: the vocabulary and models behind gestural interaction

Week 6 is a design-and-systems week rather than a mathematics week, so this page does the equivalent job: it pins down the definitions the lecture relies on, turns the six-way gesture taxonomy into a decision table, gives a compact notation for the path from sensor samples to executed command, sets out the criteria for choosing a motion-capture system, and ends with worked answers on gesture elicitation and gesture-set auditing.

Definitions that must be exact

Marks in this unit are lost on definitions more often than on ideas. Write each of these in one sentence, with the consequence included.

Gestural interaction

Input in which the system infers intent from the movement, configuration or contact pattern of the hand and body rather than from the actuation of a dedicated control. Two families: surface gestures on a touch-sensitive plane, and mid-air gestures in the space around the device.

Direct input

Input performed on the display itself, so the finger is the pointer and the object is touched where it appears. It removes the acquisition step and imports every property of the hand: a large ambiguous contact region, self-occlusion, resting contacts, and no hover state.

Extrinsic vs intrinsic sensing

Extrinsic: the body is tracked by sensors placed in the environment — structured light, time-of-flight, passive or active IR markers, RGB cameras with pose estimation. Intrinsic: the body is tracked through sensors directly attached to it — accelerometer, gyroscope, magnetometer. The first is limited by tracking volume and occlusion, the second by drift.

Microgesture

A gesture small enough that it is only practical to sense it at the source, on the body. Microgestures are the reason intrinsic inertial sensing appears in this week's deck at all.

Guessability (elicitation) study

A method for discovering intuitive gestures: participants are shown the effect of a command and asked to invent the gesture that would trigger it. The proposals are pooled and scored for agreement, producing a gesture set ranked by how likely users are to guess each member.

Taxonomy decision table

Exam questions in this unit usually hand you a gesture and ask what kind it is. The decision hinges on one question: what must the recogniser output?

The single discriminating question

For any gesture, ask what the machine has to produce:

\[ \text{output} \in \{\ \text{a target},\ \text{a continuous parameter},\ \text{a label}\ \} \]

A target means deictic. A continuous parameter that tracks the hand means manipulative. A label drawn from a fixed set means semaphoric. If the label is not drawn from a set but inferred by matching movement, it is motion correlation. If the movement carries meaning only alongside speech, it is gesticulation; if it is structured by a grammar, it is sign language.

Notation for the gesture path

Four relationships are worth being able to write from memory: how a gesture window is formed, what the classifier must decide, why errors only accumulate, and what a sensing choice costs.

1. A gesture is a window, not a sample

Sampling produces a stream \(s_1, s_2, \dots\); segmentation selects a contiguous window:

\[ W = \langle\, s_i, \dots, s_j \,\rangle, \qquad \phi(W) \in \mathbb{R}^d \]

Practical consequence: nothing downstream can recover information the window does not contain. If \(W\) includes half of the previous gesture, the feature vector describes a movement the user never made.

2. Recognition is a decision with an abstain option

Given the feature vector \(\phi(W)\) and a gesture set \(G\), the recogniser returns a label and a confidence, and the system decides whether to act:

\[ \hat{g} = \arg\max_{g \in G}\ P(g \mid \phi(W)), \qquad \text{act} \iff P(\hat{g} \mid \phi(W)) \ge \tau \]

With \(\tau = 0\) the system always acts, which is exactly the behaviour that makes gesture interfaces feel haunted: every unintended movement is mapped onto the nearest label. Raising \(\tau\) trades missed gestures for false activations, and the acceptable balance depends on what the action costs — muting a television is not the same as unlocking a door.

3. Errors accumulate along the pipeline

Let the stages be segmentation, features, classification and feedback. Each stage accepts the previous stage's output as if it were ground truth, so the end-to-end error is bounded below by the earliest stage's error:

\[ P(\text{wrong action}) \;\ge\; P(\text{bad window}) \]

A better classifier cannot repair a bad window, and feedback arrives after the action has already been chosen. Debug gesture systems left to right.

4. Accuracy and precision are different failures

For a tracking system, with \(x\) the true value and \(\hat{x}\) the estimate:

\[ \text{accuracy} \;=\; \bigl|\,\mathbb{E}[\hat{x}] - x\,\bigr|, \qquad \text{precision} \;=\; \operatorname{Var}(\hat{x}) \]

The deck draws all four quadrants. An accurate but imprecise system jitters around the right answer; a precise but inaccurate system is confidently wrong and is the more dangerous of the two, because repeated readings agree with each other and therefore look trustworthy.

Where gesture sits in the Week 1 model. Gesture changes two things at once: it moves where the input comes from (from a control to the body) and it changes \(E_a\), the attention the system demands. Touching an object you can see usually lowers \(E_a\); an invisible mid-air gesture set usually raises it, because the user must remember what to do and watch for confirmation.

Precise but inaccurate
Accurate but imprecise

Worked comparison — three concrete systems, scored on the deck's axes.

1

A gallery installation where visitors wave at a projected artwork. Information needed: presence and coarse 2D position of a hand — nothing more. Extrinsic depth camera. Tracking volume is the only real constraint, and visitors can be guided into it by the projection itself. Accuracy and precision requirements are low; drift is irrelevant because every visitor starts fresh.

2

A wearable that detects a double-tap of the index finger against the thumb. Information needed: microgesture — millimetre motion at the hand. Intrinsic IMU on the wrist. Occlusion is irrelevant, tracking volume is the whole world, and the short window means drift has no time to accumulate. The cost is encumbrance: something must be worn.

3

A clinical gait lab measuring whole-body configuration for an hour. Information needed: full body configuration, continuously, with a stable reference. Extrinsic optical mocap with markers. Drift would invalidate the measurement, occlusion is controlled by rigging enough cameras, and the space requirement is accepted because the room is purpose-built.

4

The sentence that earns the mark. “The choice follows from the amount of information the interaction needs, and every other axis is a cost accepted to obtain it: extrinsic tracking buys absolute reference and a bounded volume; intrinsic tracking buys mobility and microgesture resolution at the price of drift and encumbrance.”

Drift: why acceleration survives and position does not

The deck lists drift next to the sensing family diagram and shows it three times — once for position, once for velocity, once for acceleration. That ordering is the whole idea.

Integrating a biased signal grows the error

An accelerometer reports \(a_t = a^{\ast}_t + b + \eta_t\), where \(a^{\ast}\) is true acceleration, \(b\) a small constant bias and \(\eta\) noise. Velocity and position follow by integration:

\[ v_t = \int_0^t a\,\mathrm{d}t, \qquad p_t = \iint a\,\mathrm{d}t^2 \]

A constant bias therefore produces an error that grows linearly in velocity and quadratically in position:

\[ \varepsilon_v(t) \approx b\,t, \qquad \varepsilon_p(t) \approx \tfrac{1}{2}\,b\,t^2 \]

This is why the deck's drift diagram names all three quantities in that order. Acceleration is measured directly and carries only the bias; velocity carries its integral; position carries the double integral and diverges fastest.

What drift means for a gesture

A short gesture is safe: over a 500 ms flick the accumulated error is negligible, which is why wrist-worn microgesture detection works at all. A long interaction is not: an hour of integration turns a millimetre-scale bias into metres of position error, so intrinsic sensing must be re-referenced against something absolute.

What the designer actually does

Three standard responses: use intrinsic sensing only for the quantities it is good at (orientation, rate, relative motion); re-zero against a known posture or a landmark at the start of each gesture; or fuse with an extrinsic reference that never drifts, accepting the camera back into the system.

Elicitation and gesture-set audit

Two procedures from the week are worth being able to write out in order: how a guessability study is run, and how a proposed gesture set is audited before it ships.

Describe the effect, not the gesture

If you show the gesture, you have measured imitation. The method's whole value comes from asking people to produce the mapping themselves.

Count agreement, not votes

One command with eleven different proposals from twenty people is a different design problem from one command with fifteen identical proposals.

Audit against the sensor

A gesture can win on agreement and still be undetectable. Check each winner against the tracking volume, the occlusion pattern and the resolution of the chosen sensor.

Audit against the body

Finally ask the two questions the deck raises: can this be performed fifty times in a row without gorilla arms, and would the user be willing to do it in front of strangers?

Why this page's procedure ends with a control, not a gesture. Low agreement is not a reason to try harder; it is evidence that the command has no intuitive gesture. The honest design response is a visible affordance — which is exactly the deck's conclusion that intuitions exist only for “a couple of the most commonplace manipulations”.
In a guessability study, why must participants be shown the effect rather than a candidate gesture?
Because describing the effect is faster than demonstrating a gesture
Because showing a gesture would measure imitation, so the agreement scores would describe the experimenter's choice rather than the users'
Because participants are not qualified to evaluate a gesture's usability

Worked answer — auditing a five-command gesture set for a kitchen display. The commands are: next step, previous step, start timer, add ingredient to list, and scale recipe. Cooks have wet or full hands, so the display is controlled from a distance with no touching.

1

Classify each command before designing anything. Next/previous step are semaphoric (a dictionary of discrete labels). Start timer is semaphoric too, but its feedback must be immediate because the cook cannot look. Add ingredient is deictic if a list is on screen — the gesture has to indicate which item. Scale recipe is manipulative: a continuous quantity is being set, so a drag-like mapping fits better than a discrete symbol.

2

Run elicitation per class, not per command. Semaphoric commands are elicitable, so participants invent gestures for them. The deictic command needs pointing techniques compared (image-plane versus fixed-point) rather than gesture invention. The manipulative command needs a continuous mapping, and its question is the degrees-of-freedom match, not agreement.

3

Audit the winners against the sensing. The display is controlled from a distance, so sensing is extrinsic and therefore limited by tracking volume and occlusion. A gesture that travels outside the capture volume, or that is performed while the other hand crosses in front of the body, is undetectable no matter how intuitive it is.

4

Audit against the body. Cooks repeat actions for an hour. Any gesture requiring a raised arm will produce gorilla arms before the meal is finished, so the set must be performable low and close to the torso — or with wrist movement only. This single constraint usually eliminates the most “intuitive” wave-based winners.

5

Audit the feedback. A cook is looking at food, not at the display. Every command needs a non-visual confirmation — a sound, a change in the timer's audible tick — because the deck's feedback challenge is at its hardest when the user cannot afford to look. Commands whose feedback cannot be made perceptible without sight should keep a visible control instead.

6

The takeaway sentence. “Elicitation supplies the gesture set; classification tells you what each command needs; and the audit against sensor, body and feedback is what turns an intuitive set into a usable one. Any command that fails the audit gets a control, not a gesture.”
