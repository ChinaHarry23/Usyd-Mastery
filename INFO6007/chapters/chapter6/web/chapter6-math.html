INFO6007 — Week 6 supplement

Foundations: the numbers behind resource management

Week 6 is mostly behavioural, but four pieces of it are arithmetic: the resource load formula, the critical path and float that decide what levelling is allowed to move, the utilisation numbers a histogram shows, and the earned-value indices that turn resource usage into a cost forecast. This page works all four with real numbers.

Definitions verified against the Week 6 deck Worked examples use one running project Formula sheet for the exam

Definitions and units that must be exact

Marks in this unit are lost on definitions more often than on ideas. Write each of these in one sentence, with the consequence included.

Project resource management

The process of identifying, acquiring and managing the resources — both human and physical — required for the successful delivery of a project. The six processes are planning, estimating activity resources, acquiring, developing the team, managing the team and controlling resources.

Resource breakdown structure (RBS)

A hierarchical decomposition of project resources by category and type: level 1 broad categories (human, equipment, software, materials), level 2 subcategories (roles for people, platforms for software), level 3 the specific named resource (a person, a tool version, a server, a licence). It complements the WBS, which decomposes tasks instead of resources.

Resource loading

Assigning specific resources to project activities over time and measuring their workload, expressed as hours, days or FTE (full-time equivalent) per period. Its purpose is to find over-allocated and underutilised resources before the schedule is committed.

Resource histogram

A bar chart of how much of each resource is allocated over time: X-axis time periods, Y-axis resource usage, bars the allocation in each period. It visualises workload distribution and makes potential over-allocation visible.

Resource levelling

Resolving resource over-allocation by adjusting the schedule or redistributing resources, with the goal that no resource is overburdened while the project timeline is maintained as far as possible. The four techniques are delay, split, reassign and adjust work hours.

1. Resource load is a ratio, so name both halves

The deck's formula compares what a resource is given with what it has:

\[ L = \frac{\sum h_{\text{allocated}}}{h_{\text{available}}} \]

Expressed in people rather than hours, the same ratio is the full-time equivalent:

\[ \text{FTE} = \frac{\text{hours the person works in the period}}{\text{hours in a full-time period}} \]

Consequence: "120% allocated" means the numerator exceeds the denominator. It is a statement about capacity, and no amount of budget fixes it.

2. Over-allocation is a property of a period, not of a project

With \(r_a\) as the demand of activity \(a\) and \(W_a\) its window, demand in period \(t\) and utilisation are:

\[ D_t = \sum_{a\,:\,t \in W_a} r_a, \qquad U_t = \frac{D_t}{C}, \qquad U_{\max} = \max_t U_t \]

The resource is over-allocated exactly when \(U_t \gt 1\) for some \(t\). This is why an average utilisation below 100% proves nothing: the peak is what breaks the plan.

3. Levelling may only delay what has float

Delaying activity \(a\) by \(\delta\) periods shifts its window \(W_a \to W_a + \delta\) and consumes \(\delta\) of its float. The end date is protected if and only if

\[ \delta \le F_a = LS_a - ES_a \]

For an activity on the critical path \(F_a = 0\), so the only remaining techniques are splitting, reassigning or adjusting hours — or accepting a later end date.

4. The critical path is two passes and a subtraction

Forward pass, then backward pass, then float:

\[ ES_a = \max_{p \in \text{pred}(a)} EF_p, \qquad EF_a = ES_a + d_a \] \[ LF_a = \min_{s \in \text{succ}(a)} LS_s, \qquad LS_a = LF_a - d_a \] \[ F_a = LS_a - ES_a, \qquad T = \max_a EF_a \]

Critical activities have \(F_a = 0\). The critical path is the chain of them from start to finish, and it is the chain that resource levelling is not allowed to break.

5. Three-point estimating expresses resource uncertainty

With optimistic \(O\), most likely \(M\) and pessimistic \(P\) values for the same resource estimate:

\[ E = \frac{O + 4M + P}{6}, \qquad \sigma = \frac{P - O}{6} \]

The expected value \(E\) goes into the estimate; \(\sigma\) is what the contingency reserve and the risk register are sized against.

6. Resource cost is reported through earned value

Variances, indices and the forecast:

\[ CV = EV - AC, \qquad SV = EV - PV \] \[ CPI = \frac{EV}{AC}, \qquad SPI = \frac{EV}{PV} \] \[ EAC = \frac{BAC}{CPI}, \qquad ETC = EAC - AC, \qquad VAC = BAC - EAC \] \[ TCPI = \frac{BAC - EV}{BAC - AC} \]

Reading rule: \(CPI \lt 1\) means the resources are costing more than the value they have produced; \(SPI \lt 1\) means less work has been earned than planned. When \(CPI \lt SPI\), the problem is resource cost rather than resource throughput.

A specialist team has 4 engineers. Activity X needs 3 engineers for weeks 3–5, activity Y needs 2 engineers for weeks 4–6, and both are already committed. What is \(U_{\max}\), and what does it mean?
\(U_{\max} = 0.83\), which is acceptable because capacity is never exceeded on average
\(U_{\max} = 1.25\) in the overlap weeks — demand exceeds capacity, so the plan is infeasible as written
\(U_{\max} = 5\), meaning five engineers must be hired

Worked example 1: from WBS to critical path

Everything in this section runs on one project, reused in the levelling and cost sections. It is a small mobile release, and the numbers are chosen so the arithmetic is checkable by hand.

Step 1 — decompose the work (WBS)

The work breakdown structure decomposes deliverables, not resources. Only the leaves are work packages that can be estimated and assigned.

\(ES_a = \max EF\) of predecessors, \(EF_a = ES_a + d_a\). Work in weeks elapsed, so the project starts at week 0.

\(ES_A = 0 \Rightarrow EF_A = 0 + 2 = 2\)
\(ES_B = EF_A = 2 \Rightarrow EF_B = 2 + 3 = 5\)
\(ES_C = EF_A = 2 \Rightarrow EF_C = 2 + 4 = 6\)
\(ES_D = EF_B = 5 \Rightarrow EF_D = 5 + 5 = 10\)
\(ES_{T1} = EF_B = 5 \Rightarrow EF_{T1} = 5 + 2 = 7\)
\(ES_{T2} = EF_C = 6 \Rightarrow EF_{T2} = 6 + 2 = 8\)
\(ES_{T3} = EF_{T1} = 7 \Rightarrow EF_{T3} = 7 + 1 = 8\)
\(ES_E = \max(EF_C, EF_D, EF_{T1}, EF_{T2}, EF_{T3}) = \max(6, 10, 7, 8, 8) = 10 \Rightarrow EF_E = 13\)
\(ES_F = EF_E = 13 \Rightarrow EF_F = 13 + 1 = 14\)

The forward pass gives the project duration \(T = \max_a EF_a = 14\) weeks.

Step 4 — backward pass (latest dates) and float

Start from \(LF_F = 14\) and work backwards: \(LF_a = \min LS\) of successors, \(LS_a = LF_a - d_a\), then \(F_a = LS_a - ES_a\).

\(LF_F = 14 \Rightarrow LS_F = 13 \quad F_F = 0\)
\(LF_E = LS_F = 13 \Rightarrow LS_E = 10 \quad F_E = 0\)
\(LF_D = LS_E = 10 \Rightarrow LS_D = 5 \quad F_D = 0\)
\(LF_C = LS_E = 10 \Rightarrow LS_C = 6 \quad F_C = 10 - 6 = 4\)
\(LF_B = \min(LS_D, LS_{T1}) = \min(5, 8) = 5 \Rightarrow LS_B = 2 \quad F_B = 0\)
\(LF_A = \min(LS_B, LS_C) = \min(2, 6) = 2 \Rightarrow LS_A = 0 \quad F_A = 0\)
\(LF_{T1} = \min(LS_E, LS_{T3}) = \min(10, 9) = 9 \Rightarrow LS_{T1} = 7 \quad F_{T1} = 2\)

Careful: \(T1\) also feeds \(T3\), and \(T3\) has \(LS = 9\), so \(LF_{T1} = \min(10, 9) = 9\) and \(F_{T1} = 7 - 5 = 2\). Continuing, \(LF_{T2} = LS_E = 10 \Rightarrow LS_{T2} = 8\) and \(F_{T2} = 8 - 6 = 2\); and \(LF_{T3} = LS_E = 10 \Rightarrow LS_{T3} = 9\) with \(F_{T3} = 9 - 7 = 2\).

Result. The critical path is A → B → D → E → F with a duration of 14 weeks. Every test activity carries two weeks of float, and UI build carries four. Those float values are the only currency resource levelling can spend — the next section spends them.

Worked solution — checking the two passes by hand. A common exam question is a network with only some cells filled in. Work it in this order.

1

Forward pass, in topological order. Take the largest \(EF\) among predecessors. D ends at week 10 and C ends at week 6, so E cannot start before week 10 even though C finished four weeks early — E needs both. That single \(\max\) is what creates C's float.

2

Duration. \(T = \max EF = 14\). If a question gives a required end date shorter than \(T\), the honest answer is that the schedule is infeasible and the options are scope, resources or the date — not a smaller float.

3

Backward pass, in reverse topological order. Take the smallest \(LS\) among successors. T1's successors are E (LS 10) and T3 (LS 9), so \(LF_{T1} = 9\), not 10. Missing a successor is the most common arithmetic error in this question.

4

Float and critical path. \(F = LS - ES\). A, B, D, E and F all have \(F = 0\), so they form the critical path; C, T1, T2 and T3 have \(F = 4, 2, 2, 2\). Sanity check: every path from start to finish must have at least one zero-float activity, and the sum of float along any path equals the total.

5

Translate into resource language. T2 can start anywhere between weeks 7 and 9 without moving the release date; C can start anywhere between weeks 3 and 7. A specialist shortage in those windows is therefore a levelling problem, not a schedule problem — and a shortage in B or D is a project problem.

A project's network has a total duration of 14 weeks. A task with \(ES = 6\), \(d = 2\) and all of its successors starting at week 10 is delayed by 3 weeks. What happens?
Nothing: the project still finishes in week 14 because float absorbs it
The two weeks of float are used up and the finish date slips by one week
The task becomes critical and the project slips by three weeks

Worked example 2: resource levelling arithmetic

Now put the QA testers from the network onto a calendar. The team has two testers, so \(C = 2\). A week is the period, and an activity with \(ES = s\) and duration \(d\) occupies weeks \(s+1\) through \(s+d\).

Step 2 — read the two numbers that matter

Average utilisation and peak utilisation answer different questions:

\[ U_{\text{avg}} = \frac{\sum_t D_t}{5 \cdot C} = \frac{9}{10} = 0.90, \qquad U_{\max} = \max_t U_t = \frac{4}{2} = 2.00 \]

The pool looks 90% loaded and is in fact impossible: in week 7 the plan demands four testers from a team of two. This is the single most examinable idea on the page — average utilisation never proves feasibility.

Step 3 — choose the movable activity

The over-allocated weeks must lose work. Which activity moves is decided by float, not by preference:

T1: \(F = 2\), and it is the predecessor of T3 — moving it moves T3
T2: \(F = 2\), and its only successor is E — therefore movable by up to 2 weeks
T3: \(F = 2\), but dropping it into an overloaded week makes the peak worse

Delay T2 by \(\delta = 2\) weeks, the largest \(\delta\) permitted by \(\delta \le F_{T2} = 2\).

Step 4 — the levelled plan

T2 now occupies weeks 9–10 instead of 7–8. Nothing else moves.

\(U_{\max}\) falls from 2.00 to 1.00, the same 9 tester-weeks are delivered, and the finish date is unchanged at week 14 because T2 now starts exactly at its late start \(LS = 8\). The price is that T2 has no float left: any further slip on it moves E and therefore the release.

Step 5 — price the alternative: overtime instead of levelling

Suppose the team refuses to move T2 and the peak week is covered with overtime. With an illustrative loaded rate of \(\$80\) per hour and a 38-hour week, one tester-week costs \(38 \times 80 = \$3{,}040\), and the over-allocation in week 7 is 2 testers:

\[ \text{extra cost} = 2 \times 3{,}040 \times 0.5 = \$3{,}040 \]

The 0.5 is the overtime premium: the two tester-weeks are paid anyway, and the half-load premium is what levelling avoids. Add the burnout risk the deck warns about, and delaying a floating activity is cheaper than paying the peak — which is exactly why levelling looks for float first.

Worked solution — levelling by splitting instead of delaying. The same plan, but the regression suite T2 is split into two one-week halves of two testers each.

1

Place the halves where the pool is empty. T1 fills weeks 6–7 at 2 testers and T3 sits in week 8 at 1 tester. The only weeks with free capacity are 8 (one tester free) and 9–10 (two free). Put one half in week 9 and the other in week 10.

2

New demand vector. \(D = (2, 2, 1, 2, 2)\), so \(U_{\max} = 1.00\) — the same peak as the delayed plan, reached by a different route.

3

Check the constraint. T2's second half finishes in week 10, which equals \(LF_{T2} = 10\), so E still starts in week 11 and the 14-week duration holds. Split float = 2 weeks, exactly as before.

4

Compare the costs. Splitting preserves the option to start T2 earlier if capacity appears, and it keeps testers on one activity at a time — but it pays for two test-environment set-ups and risks an inconsistent regression baseline if code changes between the halves. Delaying is simpler; splitting is better when the second half genuinely can wait.

5

State the rule. Every levelling technique costs something. Choose the one whose cost falls on the activity with the most float, and re-check \(U_{\max}\) afterwards — levelling a peak into a different peak is a common and expensive mistake.

After levelling, \(U_{\max} = 1.00\) and the finish date is unchanged. What has the project given up?
Two weeks of float on the delayed activity, which is the buffer that would have absorbed a future slip
Nothing: levelling adds capacity at no cost by definition
The project duration: it now finishes later, which is why the peak fell

Worked example 3: resource cost performance

The deck's closing case study is a 12-week Cloud Banking Application with a budget of $100,000 and resources in trouble by week 6. Resource usage is only visible as money once it is compared with earned value.

The data at the end of week 6 (illustrative figures consistent with the case)

Budget at completion \(BAC = \$100{,}000\). Planned value \(PV = \$52{,}000\). Earned value \(EV = \$44{,}000\). Actual cost \(AC = \$58{,}000\). Everything below is arithmetic on those four numbers.

Step 1 — variances: how far off, in dollars

\[ CV = EV - AC = 44{,}000 - 58{,}000 = -\$14{,}000 \] \[ SV = EV - PV = 44{,}000 - 52{,}000 = -\$8{,}000 \]

Both variances are negative, so the project is over budget and behind schedule. Note the asymmetry that matters for resource management: the cost variance is nearly twice the schedule variance.

Step 2 — indices: how far off, as a rate

\[ CPI = \frac{EV}{AC} = \frac{44{,}000}{58{,}000} = \frac{22}{29} = 0.759 \] \[ SPI = \frac{EV}{PV} = \frac{44{,}000}{52{,}000} = \frac{11}{13} = 0.846 \]

Interpretation: every dollar spent has bought 76 cents of earned value, and 85% of the planned work has been earned. \(CPI \lt SPI\) says the binding constraint is the cost of resources, not the throughput of the team.

Step 3 — forecast: what the finish now costs

\[ EAC = \frac{BAC}{CPI} = \frac{100{,}000}{0.759} = \$131{,}818 \] \[ ETC = EAC - AC = 131{,}818 - 58{,}000 = \$73{,}818 \] \[ VAC = BAC - EAC = 100{,}000 - 131{,}818 = -\$31{,}818 \]

If the current cost efficiency persists, the project finishes about 32% over budget: \(\frac{31{,}818}{100{,}000} = 0.318\).

Step 4 — recovery: the efficiency the remaining work must reach

\[ TCPI = \frac{BAC - EV}{BAC - AC} = \frac{100{,}000 - 44{,}000}{100{,}000 - 58{,}000} = \frac{56{,}000}{42{,}000} = 1.33 \]

Every remaining dollar must now deliver \(\$1.33\) of value — against a historic rate of 0.76. A TCPI far above 1 is the quantitative form of the deck's instruction to correct and reallocate resources early rather than at the end.

The lesson the table teaches. A total variance of +$6,000 looks survivable; the composition does not. The saving came from a resource that stopped being available (which also cost earned value), while the overrun came from a resource that is still being consumed above plan and will keep overrunning. When you report resource cost, decompose it by resource line — a single net figure hides both the cause and the trend.

Worked solution — deciding what to fix first. Given \(CPI = 0.76\), \(SPI = 0.85\) and \(TCPI = 1.33\), what should the project manager actually do?

1

Separate the two problems. The schedule index is the milder one. Since \(CPI \lt SPI\), the cost per unit of progress is the worse number, so an across-the-board push for speed would spend money the project does not have.

2

Attack the resource line with the largest variance. Cloud capacity is +$8,000 against plan. The control-resources cycle — record, compare, analyse, correct, update — ends in one of four decisions: keep, reallocate, replace or release. Right-sizing and releasing idle capacity is the only lever here that changes both the trend and the forecast.

3

Do not bank the labour saving. The −$2,000 is the shadow of an availability loss, and it is why \(EV\) is $8,000 below \(PV\). Treating it as a saving would repeat the mistake the case study describes.

4

Check the recovery index against reality. \(TCPI = 1.33\) means the remaining work must be a third more cost-efficient than the plan assumed. That is achievable only by changing how the work is resourced — automating the deployments the DevOps engineer is struggling with, levelling the testers' multitasking, and re-planning the cloud footprint — not by asking people to work harder.

5

Report it as a range. \(EAC\) computed from \(CPI\) assumes the current efficiency persists. Present \(EAC = \$131{,}818\) as the "no change" forecast and state what the forecast becomes if the cloud action lands — that is what turns a variance report into a decision.

At week 6 of a $100,000 project, \(EV = \$44{,}000\), \(AC = \$58{,}000\) and \(PV = \$52{,}000\). Which single statement is true?
\(CPI = 1.32\), so the project is under budget
Both indices are below 1, so the project is over budget and behind schedule
\(SV = +\$14{,}000\), so the project is ahead of schedule

Choosing the right technique

Week 6 exam questions are usually “which technique, and why?”. Run the situation through this order and the justification writes itself.

SituationFirst moveMarks are lost when…
Peak demand exceeds capacity in one periodFind the float among the overlapping activitiesYou propose hiring before checking whether the peak is movable
Over-allocation on the critical pathReassign, split or adjust hours; or re-baseline the dateYou delay a zero-float activity and claim the end date is unchanged
Demand below capacity for a whole roleRelease or reallocate the resource and update the planYou treat underutilisation as harmless; idle specialist capacity is a cost
Cost variance worse than schedule varianceDecompose actual cost by resource lineYou report a single net variance with no resource attribution
A named specialist is shared across projectsNegotiate and record the commitment in the resource calendarYou assume availability equals headcount
The sentence that earns the mark: “The resource is over-allocated in week 7 because demand of four testers exceeds capacity of two; the regression suite has two weeks of float while module testing has none, so levelling delays the regression suite by two weeks, which brings the peak to 100% without moving the 14-week end date.” Definition, evidence, technique, consequence.

Recall and exam templates

Cover the answers and work down the deck. If you can state each one from memory and write the formula, the arithmetic questions in this unit hold no surprises.

Template: “describe the process”

Name the process, state its input, state its output, then give one IT example. “Acquiring resources obtains the people and environments the plan requires; its outputs are the project team assignments, physical resource assignments and resource calendars.”

Template: “which technique and why”

Give the evidence (demand against capacity, or float), name the technique, then state the consequence and its cost. Never name a technique without saying what it consumes.

Template: a numbers question

Write the formula, substitute, state the unit, then interpret in one sentence. “\(CPI = 0.76\), so the project earns 76 cents of value per dollar spent” earns the interpretation mark that a bare number does not.

Template: a case question

Classify each symptom as availability, productivity, over-allocation or cost, then match each to a control-resources action: keep, reallocate, replace or release.
