Basic vs Container Types

Lecture framing: data types split into basic types that hold a single value and containers that hold multiple values. The lecture pictures basic types as individual Lego bricks and containers as bricks assembled into a structure.

Basic (single value)

  • Integers
  • Floating points
  • Boolean
  • Characters

Containers (multiple values)

  • Strings
  • Lists
  • Tuples
  • Dictionaries
Where we are: Week 4 of the unit map is "containers". This lecture introduces lists in depth, then tuples, dictionaries, and command line arguments.

Why Lists Exist: Esfandiar's Seven Labours

The lecture motivates lists with Esfandiar's Seven Labours from the Shahnameh: two monstrous wolves, two man-eating lions, a dragon, evil magic, the Simurgh, a storm, and the desert. How should a program store seven related values?

# Storing Esfandiar's Seven Labours # Not the best way battle1 = "wolves" battle2 = "lions" battle3 = "dragon" battle4 = "evil_magic" battle5 = "simurgh" battle6 = "storm" battle7 = "desert" print(battle1, battle2, battle3, battle4, battle5, battle6, battle7)
# Storing Esfandiar's Seven Labours # A better way battle_list = ["wolves", "lions", "dragon", "evil_magic", "simurgh", "storm", "desert"] print(battle_list)

Lecture definitions: a data structure is a way to organize data that we wish to process with a computer program. A list is a contiguous block of memory containing multiple values, not all of the same type. A list solves the problem of having many variables.

1

With battle1 to battle7, every new labour means inventing another variable name and editing the print(...) call. The code grows in step with the data.

2

With battle_list, one name holds all seven values, len(battle_list) reports how many there are, and print(battle_list) never needs to change when the data does.

3

This is the lecture's first real data-structure decision: organize the data so the program can process it as a group, which is exactly what later topics like loops will rely on.

Python Lists: Syntax and Initialisation

Defining a list

A multi-element list is defined as comma-separated objects within the square brackets [ and ]. Elements of the same type make a homogeneous list; elements of different types make a heterogeneous list.

Lists are not arrays

The lecture stresses that Python's list is not the same as an array. Arrays and lists are not the same thing in Python, even though other languages blur the two.

# Initialize lists empty_ls = [] tutors = ["Avinash", "Joshua", "Luis"] x = [5, 10, 15, 20, 25] help_ls = list("help")

Spot the four initialisations: an empty list, a homogeneous list of strings, a homogeneous list of integers, and list("help"), which converts the string into ['h', 'e', 'l', 'p'] — one element per character.

Zero-based Indexing

Python is zero-based. Some programming languages use one-based indexing, where the first element starts at one instead of zero. The lecture spells out the consequence of each convention.

Other languages

Zero-based (index-0)

Slicing

Lecture rule: the slicing operator returns a slice of the given list using the syntax list[start:end]. The start index is the start of the slice (inclusive); the end index is the end of the slice (exclusive). Adding a third number, list[start:end:step], makes step the interval between elements included in the slice.

alphabet = ['a', 'b', 'c', 'd', 'e', 'f']

Two-Dimensional Lists

Lists can be two-dimensional. The lecture's examples are all game boards — noughts and crosses, Go, Sudoku, chess — where a grid is naturally a list of rows, and each row is itself a list.

game = [ ['x', '-', 'o'], ['-', 'x', 'o'], ['-', '-', 'o'] ]
ExpressionPrintsWhy
print(game)[['x', '-', 'o'], ['-', 'x', 'o'], ['-', '-', 'o']]The whole list of rows
print(game[1])['-', 'x', 'o']Index 1 selects the second row, itself a list
print(game[1][2])oThe first index picks the row, the second picks the element inside it
Read it inside-out: game[1][2] is just indexing applied twice — game[1] is a list, so [2] indexes into that list.

Tuples, Mutability, and Strings

Tuples

You can use tuples for storing a fixed list of elements. Tuples are like lists, but their elements are fixed: once a tuple is created, you cannot add, delete, or replace any element accidentally. A multi-element tuple is comma-separated objects within the parentheses ( and ).

Shared operations

Lists and tuples share the same reading operations: length with len(empty_ls), accessing the i-th item from origin 0 such as tutors[1], and slices from index i to j-1 such as tutors[1:2].

Mutable vs immutable: lists are mutable — you can modify their elements after creation. Tuples are immutable — like string objects, once you create a tuple you cannot modify its elements. The lecture notes that tuples are used to pass multiple values out of a function to reduce the risk of the return values being modified.

greet = 'hello' print(greet[0]) # h print(greet[1]) # e print(greet[4]) # o print("Hello"[0]) # works too: H
Strings belong to the family: a string is a container of characters, so indexing works on it directly — and list("help") from the initialisation slide is exactly the string-to-list conversion the lecture asks about.
Given battle_tuple = ("wolves", "lions", "dragon"), which line raises an error?
battle_tuple[1] = "beast_akvan"
print(battle_tuple[1])
print(battle_tuple[0:2])

Dictionaries

Lecture definition: dictionaries in Python store data values in key:value pairs. A dictionary is a collection which is ordered (since Python 3.7), changeable, and does not allow duplicates. Items can be referred to by using the key name, which lets you associate a value with a unique key and then access it quickly.

marks_hw = { "0646": 89, "2134": 95, "2342": 93 } # or marks_exam = dict() marks_exam["0646"] = 34 marks_exam["2134"] = 93 marks_exam["9134"] = 100 marks_exam["4134"] = 99

Two ways to create

The slide builds dictionaries with curly braces { } or with the dict() method, then adds entries by assigning to a key.

Changeable

Dictionaries are changeable, meaning you can change, add, or remove items after the dictionary has been created — perfect for marks that arrive one assessment at a time.

How do you read the homework mark for student "2134" from marks_hw?
marks_hw["2134"]
marks_hw[1]
marks_hw("2134")

Command Line Arguments

Another way in: inputs can be passed in through the command line instead of using the input() function. Command line arguments are stored in a variable — an array of string objects — called argv in the module sys. The first element will always be the script name.

$ python3 battles.py rostam
ExpressionValue for the command aboveNote
sys.argv[0]"battles.py"Always the script name
sys.argv[1]"rostam"The first real argument — a string
len(sys.argv)2Script name plus one argument
It is a container too: sys.argv is itself a list of strings, so everything from this lecture — indexing, len(), slicing — applies to it directly.

Lecture Summary

Lists are contiguous memory

One list lets you access and manipulate a whole group of related data; as the programmer, you decide what memory you need and how it is processed.

Core idea

Mixing types is allowed, not advised

You can mix different types of objects in the same Python list, but this may not work in other languages — the lecture's advice is to keep the same type of objects in your list.

Style guidance

Three fundamental operations

Python collections — list, tuples, dictionary — share the same workflow: initialize, access, and modify elements (if possible).

Quick revision

sys.argv and key:value pairs

Command line arguments arrive in sys.argv with the script name first; dictionary items are key:value pairs referred to by key name.
