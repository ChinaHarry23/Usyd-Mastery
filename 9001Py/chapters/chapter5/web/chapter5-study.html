Iteration in Life

The lecture opens with everyday repetition: make cups of tea until everyone present has a cup, shop until everyone on the gift list has a gift, and "practice makes perfect" — repeat a level until it is cleared, or attempt programming exercises until you master them.

A repeated body of actions

Each example repeats the same small sequence on every pass: prepare cup, pour tea, serve. Or: decide gift, search for item, purchase, wrap. The actions inside one pass stay the same.

A condition that ends it

Each example also keeps going until something becomes true: everyone has a cup, everyone on the list has a gift, the level is cleared. Nothing repeats forever.

"Do you notice anything?" — the lecture's question. Every repetitive task pairs a repeated body of actions with a condition that decides when to stop. A loop is exactly that pairing, written in code.

Two Types of Loops

Loops enable us to set up arbitrary patterns of repetition: do something once, a million times, or until a condition is no longer true. The lecture splits loops into exactly two types.

TypeHow many repetitions?Lecture imageSituations of use
Count-controlledA known number of timesJeannie the genie grants exactly three wishesOperating on everything in a set; scanning through a list of command-line arguments
Event-controlledAn unknown number of timesThe Sphinx keeps asking its riddle until it hears the correct answerReading a file until end of file

Count-controlled

Known Count

Repeat a set of actions a known number of times. You can write down the total before the loop starts — like running a race that is exactly five laps.

Event-controlled

Until an Event

Repeat until a sentinel value (unlikely data) is entered, a flag value (False) is encountered, or some limit is reached. The total is unknown in advance.

A program keeps reading lines from a file until it reaches the end of the file. Which loop type is this, according to the lecture?
Event-controlled, because the number of repetitions is unknown
Count-controlled, because files always have a fixed length

Anatomy of a Loop

The lecture's running example: a race requires participants to run around the track five times. How do you track the number of rounds, and when do you stop running? The answer gives the four components of every loop.

round = 1
initialize control variable
→
round <= 5 ?
test condition
→
RUN!!!
statement(s)
→
round += 1
modify, then re-test

Four required components

  1. Initialize the loop control variable
  2. Test the loop control variable
  3. Execute the statement(s) in the body
  4. Modify the loop control variable

Shorthand from the lecture

i = i + 1 # is same as i += 1 i = i - 1 # is same as i -= 1

Both spellings update the control variable; the short form is just notation.

Flowchart reading: while the test is True, control flows test → body → modify → back to test. The moment the test is False, execution leaves the loop and continues with the statement after it.

Control Flow: while

Syntax from the lecture: the body runs while the boolean expression evaluates to True; when it evaluates to False, control moves past the loop.

while <boolean expression>: Statement(s)

The lecture's "Simple Loop" turns the five-round race into code — the RUN!!! program:

i = 1 while i <= 5: print(f"Round {i}: RUN!!!") i = i + 1 print(f"Round {i}: Stop!")

Loop Tracer

Step through the RUN!!! program one condition-check at a time, exactly as the lecture's flowchart does.

    1

    After the fifth body run, i = i + 1 sets i to 6 — the modify step always executes before the condition is re-tested.

    2

    The test i <= 5 is now False, so the loop exits without printing another RUN line.

    3

    The final print sits outside the loop, so it uses whatever i holds at exit — producing Round 6: Stop!. The control variable survives the loop with its last modified value.

    Missing Components & Infinite Loops

    The lecture asks: what happens if the components are missing? Each missing piece fails in its own way.

    Missing componentWhat goes wrong (lecture)
    Initialization of the loop control variableUnable to start the loop
    Condition to test the loop control variableSyntax error; or a logic error — the loop won't start or runs the wrong number of times
    Modification of the loop control variableLogic error — wrong number of loops; worst-case scenario: infinite loops

    Infinite loop: a loop that never exits. This happens because the condition is always True. If an infinite loop is unintentional — you didn't design it — you can issue a Keyboard Interrupt command <CTRL-C> to stop execution.

    Lecture tips: preventing accidental infinite loops

    Ensure that the body contains statements to modify the loop control variable, or statements to terminate the loop when the event is achieved.

    You wrote a while loop but forgot to modify the loop control variable inside the body. What does the lecture call the worst-case outcome?
    An infinite loop, because the condition stays True forever
    A syntax error before the program even runs
    The loop body executes exactly once and stops

    The lecture stresses that there are many ways to implement the same number of known iterations. All four rows below run the body exactly 5 times:

    Off-by-one defence: the start value and the comparison operator must be read together. Changing < to <= without changing the bound adds an extra iteration.

    How to Design Loops

    Three design questions from the lecture

    1. Type of loop: count-controlled (known number) or event-controlled (unknown number)?
    2. Condition to end iteration: known — how many iterations? Unknown — is there a sentinel value, and when do you raise the flag?
    3. Body of loop contents: which sequence of actions runs each iteration, and which statement modifies the loop control variable?
    type end condition body

    Applications of loops

    • Repeat a set of actions — the RUN!!! and Jeannie examples
    • Summation — calculate a running total of a set of values
    • Iterate through elements in a collection — display each character in a string
    • Count occurrences — e.g. tally how many times 'a' appears in a word

    Extra bookkeeping variables

    • Repeating actions needs a counter variable incremented every iteration
    • Summation needs a variable to hold the sum in addition to the loop control variable
    • Counting occurrences needs count variables in addition to the loop control variable
    Habit: the lecture answers these three questions before writing any while line. Design the loop on paper or in a flowchart, then translate it.

    Application: Summation

    The lecture's worked task: write a program to compute the average of three integers given by the user. Expected behaviour from the slides:

    $ python3 average.py Number 1: 1 Number 2: 2 Number 3: 3 Average: 2.0

    Lecture algorithm (count-controlled, 3 iterations)

    1. Set the initial value for the loop control variable
    2. Initialize the variable to hold the total as 0
    3. While statement compares the loop control variable with the terminating condition:
      • Get input and save the value
      • Add to the running total
      • Modify the loop control variable to track the iteration
    4. Divide the total by 3
    5. Display the result
    i = 1, N = 3 total = 0 total = total + num
    i = 1 N = 3 total = 0 while i <= N: num = int(input(f"Number {i}: ")) total = total + num i = i + 1 print(f"Average: {total / N}")
    What the slide highlights in red: the summation-specific parts are total = 0 before the loop and total = total + num inside it. Everything else is the standard count-controlled skeleton you already know from the RUN!!! program.

    Iterating Through Elements

    Recall from Week 2: a string is actually a sequence of characters, and each character (element) can be accessed by its index. The same rule applies to other collections such as lists, tuples and numpy arrays. Python follows zero-based numbering: the first element always starts at 0 — which directly affects your loop design.

    The lecture's "Printing Class Roll" slide shows three equivalent programs over the same list:

    class_roll = ["Joshua", "Ehab", "Michael", "Daniel", "Tim", "Nicole"] # (1) for over the elements for name in class_roll: print(f"Hello {name}") # (2) for over the indices for i in range(0, len(class_roll)): print(f"Hello {class_roll[i]}") # (3) while with a counter i = 0 while i < len(class_roll): print(f"Hello {class_roll[i]}") i = i + 1

    From while loop to for loop

    i = 1 while i <= 5: print(f"Round {i}: RUN!!!") i = i + 1 print(f"Round {i}: Stop!")
    for i in range(1, 6): print(f"Round {i}: RUN!!!") print(f"Round {i+1}: Stop!")

    Spot the components

    The lecture asks you to identify the loop control variable, the terminating condition and the modification in the for version: range(1, 6) bundles initialization (start at 1), termination (stop before 6) and modification (advance each pass) into one expression.

    The lecture flags for as "extra in Python" here — it will be covered properly in Week 9.

    In program (3), why is the while condition i < len(class_roll) rather than i <= len(class_roll)?
    Because indexing is zero-based: the last valid index is len(class_roll) - 1
    Because <= is not allowed in while conditions
    Because len() returns one less than the number of items

    Event-Controlled Loops

    An event-controlled loop terminates when an event happens. The lecture names two mechanisms:

    Sentinel value

    Unlikely Data

    An unlikely value that the data can take; receiving it ends the loop. The lecture compares it to a "safe-word" in extreme haunted houses — a signal that is never confused with normal input.

    Flag

    Boolean Switch

    A boolean that controls the loop. The loop runs while the flag condition holds and the body flips the flag when the event occurs. Lecture advice: use a flag to make your code clearer, if it makes it clearer.

    The lecture's echo flowchart in code: initialise stop_flag = False, loop on not(stop_flag), and raise the flag when the sentinel "STOP IT!" arrives:

    stop_flag = False while not stop_flag: ans = input() if ans == "STOP IT!": stop_flag = True else: print(ans)

    Echo Again 2.0: modify echo.py to spell each letter in a given word, stopping when the user enters "STOP IT!". The helper flowchart spell_word(word) is itself a count-controlled loop:

    i = 0 while i < len(word): print(word[i]) i = i + 1
    One program, two loop types: the outer echo loop is event-controlled (the flag is raised by the sentinel), while the inner spelling loop is count-controlled (len(word) is known once the word arrives). As the lecture's summary puts it, programs can contain a combination of variables, functions, expressions, conditionals and/or loops.

    Lecture Summary

    Two loop types

    Count-controlled loops repeat a known number of times; event-controlled loops repeat until a sentinel value, flag change, or limit ends them.

    Classification

    Four-part anatomy

    Initialize, test, body, modify. Drop the modify step and you risk an infinite loop — the condition stays True and only CTRL-C saves you.

    while mechanics

    Design before code

    Decide the loop type, the end condition (count, sentinel or flag), and the body — including extra variables like totals or counts — before writing while.
